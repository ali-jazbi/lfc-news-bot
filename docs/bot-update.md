# آپدیت بات از تلگرام

این نسخه را یک بار به روش فعلی روی سرور دریافت و ری‌استارت کنید. سپس در `.env`:

```dotenv
UPDATE_ENABLED=true
ADMIN_USER_IDS=123456789
UPDATE_DRAIN_TIMEOUT=600
```

عدد بالا نمونه است؛ آیدی عددی خودتان را از `/id` بگیرید. چند آیدی را با کاما جدا
کنید. `ADMIN_CHAT_ID` همان گروه ادمین فعلی می‌ماند. برای `/update` فهرست خالی
اجازه به هیچ‌کس نمی‌دهد و دستور خارج از گروه ادمین اجرا نمی‌شود.

در گروه ادمین فقط `/update` یا `/update@YourBotUsername` را بفرستید. بات پردازش
جدید را موقتاً متوقف می‌کند، منتظر پایان کارهای جاری می‌ماند، در یک پردازش جدا
`git pull --ff-only --no-rebase` را روی شاخهٔ فعلی و upstream آن اجرا می‌کند،
ساختار کد را بررسی می‌کند و فقط در صورت تغییر `requirements.txt` وابستگی‌ها را
با Python همین محیط نصب می‌کند. بررسی import بدون اجرای `main()`، اسکرپ،
ترجمه یا فراخوانی Hermes انجام می‌شود.

اگر نسخه تازه‌ای نباشد، ری‌استارت نمی‌شود. در صورت موفقیت، همین پردازش بات با
Python و آرگومان‌های فعلی دوباره اجرا می‌شود؛ هیچ `pkill` عمومی اجرا نمی‌شود.
بعد از راه‌اندازی و اتصال به تلگرام، کامیت جدید در همان گروه اعلام می‌شود.
دستورهای تکراری هم‌زمان و دریافت دوبارهٔ همان پیام بعد از ری‌استارت، آپدیت
دوم راه نمی‌اندازند. خبرهای ذخیره‌شده و فایل `.env` پاک نمی‌شوند.

پوشهٔ برنامه باید یک checkout مستقل گیت، روی یک شاخه با upstream تنظیم‌شده
و بدون تغییر محلی یا فایل ثبت‌نشده باشد. فایل‌های runtime باید در `.gitignore`
باشند؛ `data/`، لاگ‌ها، `.env` و سشن‌های یوزربات در تنظیمات فعلی نادیده گرفته
می‌شوند. دسترسی غیرتعاملی گیت به مخزن باید از قبل روی همین حساب سرور کار کند.
این روش برای اجرای مستقیم `python main.py` در محیط مجازی فعلی است؛ در Docker،
به‌روزرسانی معمول با ساخت و جایگزینی ایمیج انجام می‌شود و این قابلیت را خاموش
نگه دارید.

اگر دریافت کد، بررسی یا نصب شکست بخورد، بات ری‌استارت نمی‌شود و پردازش عادی
ادامه پیدا می‌کند. تغییرات دریافت‌شده با `git reset --keep` برگردانده می‌شوند؛
اگر نصب وابستگی شروع شده باشد، نصب requirements قبلی نیز تلاش می‌شود. نصب
pip تراکنشی نیست؛ شکست بازگردانی وابستگی یا تغییر محلی هم‌زمان با آپدیت، در
پیام خطا نیاز به رسیدگی دستی را اعلام می‌کند. خروجی خام گیت/pip برای جلوگیری
از افشای URLهای دارای توکن به تلگرام یا لاگ فرستاده نمی‌شود.

وضعیت درخواست در `data/update.json` نگه‌داری می‌شود. خبر در حال پردازش اگر
ظرف `UPDATE_DRAIN_TIMEOUT` ثانیه تمام نشود، آپدیت بدون تغییر کد لغو می‌شود.

آزمون‌های آفلاین:

```text
python -m pytest tests/test_bot_update.py -q
python -m pytest tests -q
```

برای تست واقعی ابتدا روی نسخهٔ تست، یک کامیت معمولی را push کنید و `/update`
بزنید. باید پیام شروع، بررسی، ری‌استارت و کامیت جدید برسد. سپس دوباره `/update`
بزنید؛ این بار باید «آخرین نسخه است» دریافت شود. با کاربر خارج از allowlist
و از چت دیگر، دستور باید رد شود.

مرجع رفتار pull و جایگزینی پردازش: [Git](https://git-scm.com/docs/git-pull)،
[Python](https://docs.python.org/3/library/os.html#os.execv).
