# Decisions Log

Record of notable product/technical decisions made during development, with rationale, so future contributors (human or AI agent) don't re-litigate them without cause.

1. **Semi-automatic publishing (admin approval step)** — Posts are drafted and sent to an admin group first, not published straight to the channel. Rationale: translation quality and duplicate/relevance scoring aren't perfect yet; a human check avoids embarrassing mistranslations or spam on the public channel.
2. **Multi-provider translation fallback chain** instead of a single LLM. Rationale: free/low-cost LLM endpoints are occasionally rate-limited or down; chaining `opencode-deepseek → opencode-ling → groq → deep-translator` maximizes uptime without paid infrastructure.
3. **Display names for Twitter sources use real English names** (e.g. "Fabrizio Romano"), not Persian translations or raw handles. Rationale: users recognize journalists by their real name; Persian transliteration was confusing (reverted after user feedback).
4. **Video re-upload from Twitter/X via direct mp4 URL.** The pipeline detects video tweets from the Nitter RSS poster (`ext_tw_video_thumb`/`amplify_video_thumb`), then fetches the direct `video.twimg.com/...mp4` URL via the free no-key `fxtwitter` API (fallback: `vxtwitter`). Telegram's `sendVideo` accepts the URL directly; if it can't fetch it, the bot downloads the mp4 in-memory and uploads it. This replaced the old "link-only for video" decision after the user requested video delivery. Rationale: fxtwitter/vxtwitter need no API key and only the numeric tweet ID; the mp4 URL is a direct CDN link that Telegram can ingest.
5. **Instagram is out of scope for now.** Rationale: no RSS-equivalent; official Graph API only covers owned accounts; unofficial scraping requires logging in with a real account, risking a ban and frequent breakage. Revisit only if a specific high-value source requires it.
6. **No full-text republishing of paywalled articles (e.g. The Athletic).** Rationale: ToS/copyright risk. Decision: only use the source's own tweet/summary + link, never scrape the paywalled article body.
7. **Nitter mirrors + RSS fallback instead of the official paid X API.** Rationale: official API pricing is prohibitive for a hobby project; multiple mirrors + rotation + cooldown reduce single-point-of-failure risk (see THREAT_MODEL.md for the residual risk this creates). **2026-08 update:** the Twitter syndication endpoint (`cdn.syndication.twimg.com`) is silently blocked (HTTP 200 empty body) and most mirrors are dead — `nitter.net` is the only reliable free text source. To avoid rate-limit 429s, polling is now staggered (`ACCOUNTS_PER_CYCLE=6` rotation instead of all 29 every cycle, 4 workers, inter-account delay). A 429 is no longer treated as "no news" — rate-limited accounts are retried next cycle instead of a 30-minute cooldown.
8. **Local file-based persistence instead of a hosted database.** Rationale: project scale doesn't yet justify the operational overhead of a managed DB; keep hosting options cheap/free (see RELEASE_POLICY.md).
9. **`--once` / dry-run execution mode kept in `main.py`.** Rationale: enables both local testing without spamming the live channel, and (later) scheduled-job style deployment (e.g. GitHub Actions) as a zero-maintenance alternative to an always-on server.
10. **Legacy `romano.py` feed checker is a retirement candidate** now that the generic `sources/twitter.py` also covers Fabrizio Romano via the handle list. Not yet removed to avoid regressions; revisit once the generic path is proven stable.
11. **Hermes Agent is the editorial brain, not the backend (2026-08).** Hermes Agent v0.18.2 (Nous Research) is wired in as a pluggable decision layer via `ai/hermes_client.py` — agent CLI for tool-using verification, direct LLM for cheap classification/QC, deterministic fallback as last resort. Gated behind `HERMES_ENABLED` (default false) so the production bot behaves identically until enabled. Rationale: editorial judgement (relevance/rumour/importance/translation quality) is reasoning work, not infrastructure work.
12. **News state machine + retry instead of silent loss (2026-08).** New states (discovered → analyzing → verification → approved_by_ai → translation → translation_review → media_processing → pending_admin → approved → published, plus rejected/failed/retry_pending) tracked with `error`, `retry_count`, `last_attempt_at` columns (backwards-compatible ALTER TABLE). Any Telegram send failure now leaves the item in `retry_pending` and `run_cycle` retries it; after `MAX_SEND_RETRIES` it goes to `failed` with the stored error — never silently disappears.
13. **Sources are fetched concurrently with per-source health/backoff (2026-08).** `source_health.py` tracks healthy/degraded/failed per source with exponential backoff + jitter; `collect()` runs sources in a thread pool so one slow/dead source cannot block the cycle. A dead source is retried next cycle; it never stops the pipeline.
14. **Video is processed locally, not by Hermes (2026-08).** `media.py` downloads to disk, validates with ffprobe (duration/size/codec), transcodes to h264/aac mp4 with FFmpeg when needed, generates a thumbnail, and uploads the local file with retry. Failure yields a named state (`video_upload_failed`, `invalid`, `too_large`) + retry, not a silent dead-end.
15. **Never choose a random image (2026-08).** `ai/image_selector.py` evaluates candidate images with AI; if confidence < `IMAGE_MIN_CONFIDENCE` the post goes out WITHOUT an image. Better no image than a wrong image. With AI off, only the source's own image is kept (current behavior).
16. **Translation QC with revision loop (2026-08).** The existing translation chain is kept; `ai/quality_control.py` adds deterministic fact checks (numbers/names/dates via glossary values) plus an AI review against approved channel posts, with a revision loop capped at `HERMES_MAX_REVISIONS` and `human_review` after that. No infinite loops, no hallucination pass-through.
17. **MCP as the controlled bridge (2026-08).** `lfc_mcp_server.py` exposes 10 read/write tools (get_news, channel_examples, source_health, save_verification, …) over stdio MCP. Hermes never touches the DB directly — only through these tools. Registered via `hermes mcp add lfc-news`.
